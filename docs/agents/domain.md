# Domain Docs

本项目采用 single-context 领域文档布局。

## 阅读规则

遵循 AGENTS.md 的文档阅读要求。

探索相关领域前，还应读取：

- 根目录 CONTEXT.md：领域术语及其定义。
- docs/adr/ 中与本次任务相关的架构决策。

分别读取已存在且与任务相关的文档；缺失的文件或目录直接跳过，不视为问题，也不预建占位文件。

在实际术语或决策得到明确后，再按需创建。

## 文档职责

- CONTEXT.md：领域术语与业务语义。
- docs/adr/：具体架构决策及其理由。
- docs/principles.md：核心原则唯一事实来源。
- docs/architecture.md：目标架构与模块关系。

领域文档引用已有原则与架构约束，不重复维护其定义。

## 术语一致性

在需求、任务、设计和测试中使用 CONTEXT.md 已定义的术语。需要的概念未被定义时，先检查是否引入了不必要的新术语；确有缺口时，记录待澄清事项。

## 决策冲突

发现方案与现有 ADR 冲突时，明确指出对应 ADR 和冲突原因，不得静默覆盖已有决策。
